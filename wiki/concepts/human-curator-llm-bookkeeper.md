# 💡 Human-Curator / LLM-Bookkeeper Division of Labor

## 📖 Principle
The reason personal knowledge bases fail is almost never a lack of user intellect or curiosity; it is the overwhelming burden of **bookkeeping**. Maintaining consistency, syncing aliases, updating category tables, and logging timestamps drains cognitive energy.

The **Human-Curator / LLM-Bookkeeper** model establishes a strict, balanced division of responsibilities:

```
┌──────────────────────────────────────────────────────────────┐
│  👤 HUMAN ROLE (Strategic & Directional)                     │
│  • Curate and ingest high-signal raw sources                 │
│  • Ask probing, subtle, multi-document questions             │
│  • Guide the evolving thesis and validate contradictions     │
│  • Browse the visual knowledge graph in Obsidian             │
└──────────────────────────────┬───────────────────────────────┘
                               │ Orchestrates
                               ▼
┌──────────────────────────────────────────────────────────────┐
│  🤖 LLM AGENT ROLE (Bookkeeper & Knowledge Compiler)          │
│  • Read, distill, and extract raw input files                │
│  • Update 10–15 entity, concept, and source markdown files   │
│  • Maintain reciprocal [[wikilinks]] and frontmatter tags    │
│  • Audit index catalog and append to chronological log       │
└──────────────────────────────────────────────────────────────┘
```

---

## 🛠️ Practical Setup
- **Left Window**: LLM Agent terminal / chat interface (The Programmer).
- **Right Window**: [[obsidian|Obsidian]] open in real time (The IDE / Visualization layer).
- **Compounding Core**: The [[persistent-compounding-wiki|wiki]] files themselves (The Codebase).
